## 4. Strict paper rule for in-PDF answer keys (owner must)

When the answer key sits INSIDE the same PDF, it may be applied ONLY to the paper with the SAME title. Never apply one paper's key to another paper.

### `lib/services/mcq_parser.dart`
- `keyAppliedByPaper` map added next to `keyEntriesApplied`, incremented in `applyKeyIfPresent` and in the second key pass.
- **The cross-paper fallback loop was DELETED entirely** (replaced by a strict-rule comment; the mid-page-key case it served is already handled in `segmentLines` via `lastQuestionPaper`). Previously: "a key entry that matched nothing in its own segment gets a second chance in ANOTHER segment" — that is exactly the forbidden behaviour.
- Unmatched reporting loop kept; `keyPaperReport` built just before the `ParseResult` return (attribution lines `"Key '<paper>' se <n> jawab lage."` in first-application order, then orphan lines `"Key '<paper>' mili, lekin is PDF mein <paper> ke sawal nahi — key nahi lagayi."` for explicit papers with no question lines in `segmented.questionLines`); `ParseResult` gained `keyPaperReport` (constructor default `const []`, field, return value). Verified: `final unmatchedKeyEntries = <String>[];` appears once; no remaining "second chance" / "ANOTHER segment" fallback references except a still-accurate `failedTokens` comment ("the entry is consumed whether it resolves or not, so it never gets a fallback second chance in another paper").
- **Key-never-shown verification (explicit, as required):** key-section lines never reach `questionLines` — `segmentLines` drops them (verified by the PPSC-66 re-measure: 0 key fragments became questions, and the strict-paper tests assert key text never appears in parsed questions). The preview and test screens never display the raw key text — only the count (`keyPaperReport` lines, "N jawab key se lag gaye") and the per-question answers. **One disclosed exception:** `PdfImportResult.textPreview` (first 600 chars of the raw text) is shown in the `NoMcqsDialog` failure diagnostic ("What was actually read", via `ExtractedTextPreview`) — for a short/key-only file that preview can include key-section lines. That is a failure diagnostic, not the preview/test screens, and it was NOT changed; it is reported here, not hidden.

### `lib/services/answer_key.dart` — explanation drop (§5.4a/b, also part of the PPSC-66 fixes)
- `_explanationHeadingRe` (`^[-•\s]*(explanation|associated\s+information)\s*:?\s*$`, case-insensitive, whole-line only so a stem mentioning explanation never matches); `inExplanation` state, reset in key/paper/month heading branches; while inExplanation, lines are dropped unless `_startsQuestionWithOptions(texts, i)` (the next real question ends the block) — then it falls through as a question line.

## 11. Design decisions locked in (across all tasks)

- `parseKeyEntries` is the one reusable key parser (no second parser invented); "Q1 C" supported via normalisation inside `parseKeyEntries` (benefits in-book parsing too); bare "1 C" (no Q, no separator) is NOT supported (not in the required list); `applyAttachedKey` uses `segmentText` for per-paper scoping; table rows get `paper` from their cells and `number` from the Sr.# only in the row-wise pass; marker mismatch → pending + `sink.errors` note (visible via `ParseResult.errors` in the preview) + reason 'option-marker-mismatch'; Sr.# serial skip only when the buffer is empty; footer skip only in the row-wise loop; `keyPaperReport` is ready-made plain-language lines plumbed through the isolate maps, `PdfImportResult`, and `_withQuestions`; `extractKeyText` reuses the existing import methods and discards their MCQ parse.
- Green pulse: explicit greens (theme is navy), ~1.8s repeat-reverse easeInOut, static when animations disabled; tests must use bounded pumps (`pumpFrames`, 5×100 ms), never `pumpAndSettle`, where the pulsing card is on screen.
- PPSC-66: number recovery only when the run exactly fills its gap (leading run counts back from the first numbered block, numbering starts at 1; trailing runs left null); a wrapped option's tail never splits a question (continuation guard on the numberless branch only); an "Explanation:" heading only opens the drop after a complete question (options seen); running-header furniture dropped as noise; title furniture trimmed from a block's head only when a real stem line follows before the options; `questionsMissingAnswers` mirrors the pending list via `addPending` (5-option unanswered candidates excluded from it, still in `errors`); parts include pending-only parts with `pendingCount` (questionCount stays parsed-only); the book's two repeated instruction stems (Q24/Q89, Q49/Q50) are real repeats — duplicate identity is text+options, not text alone.
- Attached keys: a heading-less key gets a synthetic "ANSWER KEY" section (entries stay bare); a bare paper-title line in a pasted key is furniture (scoping comes only from a KEY heading naming a paper); an "E" entry is parsed, then reported unresolved for 4-option questions — never silently dropped.

## 12. Residual edges (accepted, not hidden)

- Key-less genuine 5-option row whose 5th option is short/label-like would be stopped by the label-stop the same way as a trailing label; an unrecognised label in a Sr.#-less table is not covered by the stop (the recovery branch still handles recognised labels only).
- Multi-line table titles: only the line directly before the header is skipped.
- A numberless stem after an explanation is swallowed (in this book the questions after explanations are numbered).
- Trailing number runs (numberless blocks after the last numbered block) are left null — never guessed.
- 5-option unanswered candidates do not appear in `questionsMissingAnswers` (still reported in `errors`).
- The '?' rule's long-'?'-wrap-tail hazard (same class as the fixed numberless-branch one) is a known limitation, not fixed.
- `_isKeyOnlyLine` widening for "(L) text" entries (defense-in-depth for heading-less keys) was NOT done — not needed for the PPSC-66 target (the p7 continuation works via inKey persistence). A heading-less in-book "1-E 2-A" key-only line still won't route (same as before, no regression); the attached-key flow covers "1-E" via its synthetic heading.
- `NoMcqsDialog` `textPreview` diagnostic can show raw text including key-section lines for a short/key-only file (see §4).
- F2's 2 remaining fragments (after the U+E000 fix): the Aurangzeb/Malir glue (one pending holds two questions' text) and the retaliation tail fragment — both are short-prose traps the plausibility guards cannot separate structurally (see §10.2). The pending gate still requires a `?`-ending stem, so the Sindh (`is:`) and crypto (no `?`) items are not pending at all.
- MPT's 3 loose-format q-only items (title `MPT CSS-2027`, warning `⚠ Q4–45: page not provided`, header `Standard idiom meaning:`) stay: the q-only path accepts non-question first lines when a short "answer" follows, and a stem-shape rule was tested and rejected (it would kill 104 of F3's documented q-only items). They are unverified (flashcard source), never presented as certain. MPT Q198 is lost to two-column interleave in the PDF's own text layer (tail/options inside Q199's block); Q3/Q106 are excluded by the book's own defect notes, by design.
- Examveda's 6 flashcard items are unchanged in kind from the old baseline (1–2 real stems, the rest fragments/prose with pool-generated options) — the loose q-only format, unverified since §8's flashcard change.
- U+E000 class, partly fixed: `_splitQuestionAndRest` now tests the cleaned line (§10.2), but `_bareAnswerRe` is end-anchored and could still fail on a trailing U+E000 marker — not fixed, out of scope for this stretch (no case observed).
